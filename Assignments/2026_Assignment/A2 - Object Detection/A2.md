## Hour 1: IoU, GIoU, DIoU, CIoU, mAP (00-IoU-and-mAP.ipynb)

### Why start here

**What to say:**

> "Before we talk about any detection model, we need to agree on what 'correct' means. If a model draws a box around a dog — how do we decide if that's a good box or a bad one? That question has a surprisingly deep answer."

Everything in detection — anchor assignment, NMS, training loss, evaluation — is built on top of one concept: **IoU**.

---

### IoU (Cells 1–4)

$$\text{IoU}(A, B) = \frac{|A \cap B|}{|A \cup B|}$$

**What to say:**

> "IoU ranges from 0 (no overlap) to 1 (perfect match). Pascal VOC says IoU ≥ 0.5 is a correct detection. COCO is stricter — it averages over IoU 0.5 to 0.95."

**Key property — scale invariance:** A tiny perfectly-aligned box scores the same IoU as a huge one. IoU measures *quality of overlap*, not absolute position.

**Pause and ask:**

> "Two boxes have IoU = 0. They don't overlap at all. What's the gradient of the loss `L = 1 - IoU`?"
>
> Answer: Zero. The optimizer has no signal. This is IoU's fundamental problem as a loss function.

---

### Why IoU fails as a training loss (Cell 7)

Two failure modes:

1. **Non-overlapping boxes → zero gradient.** No intersection = flat loss = optimizer stuck.
2. **Same IoU, different geometry.** A wide flat box and a tall narrow box can have identical IoU with the GT — but one is clearly better shaped.

This motivated the IoU family.

---

### GIoU → DIoU → CIoU (Cells 7–12)

Walk through the evolution as a story — each one fixes a problem:

| Metric | What it adds | Fixes |
|--------|-------------|-------|
| **IoU** | Intersection/Union | — |
| **GIoU** | Penalizes wasted space in enclosing box | Zero gradient when no overlap |
| **DIoU** | Penalizes center-point distance | Slow convergence when box is inside GT |
| **CIoU** | Adds aspect ratio consistency | All three geometric factors together |

**GIoU intuition:**

> "Even when two boxes don't overlap, GIoU can still penalize them — the bigger the gap between their union and the enclosing box, the more it hurts. So the optimizer always has a direction to move."

**CIoU intuition:**

> "CIoU says: I care about three things — how much you overlap, how close your centers are, and whether your aspect ratio matches. All three matter for a good box. YOLOv4+ uses CIoU as its box regression loss."

**Pause and ask:**

> "For NMS — where we're just filtering duplicate boxes, not training — which variant should we use: IoU or DIoU?"
>
> Answer: DIoU-NMS. In crowded scenes (pedestrians), two people can have high IoU but different centers — standard NMS suppresses one incorrectly. DIoU-NMS is less aggressive.

---

### mAP (Cells 17–18)

**What to say:**

> "IoU tells us if one box is correct. mAP tells us how good the whole detector is — across all confidence thresholds and all classes."

**Walk through step by step:**

```
1. For each class, rank all predictions by confidence (high → low)
2. For each prediction:
   - Match to GT box with highest IoU (greedy)
   - IoU ≥ threshold AND unmatched → TP
   - Otherwise → FP
   - Unmatched GT → FN
3. Compute Precision-Recall curve
4. AP = area under PR curve
5. mAP = mean AP over all classes
```

**COCO vs VOC:**
- **VOC mAP**: single IoU threshold (0.5), 11-point interpolation
- **COCO mAP**: average over 10 thresholds (0.5:0.05:0.95), all-points interpolation — much stricter

**Closing question for hour 1:**

> "A model gets 90% precision at 10% recall and 50% precision at 90% recall. Is that good? How would you decide without mAP?"
>
> Answer: mAP integrates the whole curve — a model that's only good at high confidence but collapses at lower thresholds will have low AP.

## Hour 2: Object Detection (A2-01-Object-Detection.ipynb)

### The framing

**What to say:**

> "In Hour 1 we defined what 'correct' means. Now let's build detectors that actually predict boxes. 10 years of architecture evolution — each model solving one specific problem with the previous one."

---

### R-CNN Family (Cells 1–4)

**R-CNN (2014):** Run ~2,000 region proposals through CNN separately → 47s/image. Unusable.

**Fast R-CNN (2015):** One CNN forward pass, extract regions from shared feature map via RoI Pooling → ~2s/image.

**Faster R-CNN (2016):** Replace Selective Search with a learned RPN that shares the backbone → ~0.2s/image.

**What to say:**

> "The two-stage story is: first find candidate regions, then classify them. Each generation made the first stage cheaper. Faster R-CNN made it essentially free by sharing the backbone. But you still can't beat two forward passes."

**Pause and ask:**
> "What's the fundamental speed limit of any two-stage detector?"
>
> Answer: You always pay for two passes — one for the backbone, one for the RPN/head. Real-time (30fps = 33ms/frame) is basically impossible for two-stage.

---

### YOLO (Cells 5–12)

**What to say:**

> "Redmon looked at the whole two-stage pipeline and asked: what if we skip stage one entirely?"

**The YOLO idea:**

Instead of "propose regions, classify each" → one network predicts all boxes and classes simultaneously from the whole image.

```
Image (416×416)
    ↓ single forward pass
Grid (13×13 for large objects, 26×26, 52×52 for small)
    ↓ each cell predicts B boxes × (4 coords + 1 conf + C classes)
```

**Key concept — grid cell responsibility:**

> "The grid cell whose center contains the ground truth box center is responsible for predicting that object. One cell, one object — this is both YOLO's strength (fast) and weakness (misses crowded scenes)."

**YOLOv3 multi-scale — connect back to mAP:**

> "YOLOv3 detects at 3 scales. Why? Because mAP@COCO averages IoU 0.5–0.95. A single-scale grid is terrible at small objects. Three scales — 13×13, 26×26, 52×52 — each handles a different object size. This is how YOLOv3 improved COCO mAP without sacrificing speed."

| Model | Speed | mAP | Use case |
|-------|-------|-----|----------|
| Faster R-CNN | ~5 fps | High | Medical, forensics |
| YOLOv3 | ~30 fps | Good | Real-time video |
| YOLOv3-tiny | ~200 fps | Lower | Edge/embedded |

---

### Darknet cfg → PyTorch (Cells 15–28)

**What to say:**

> "Darknet is the C framework YOLO was trained in. The config file is a recipe — each block is a layer. Our job: parse it and build equivalent PyTorch modules."

**EmptyLayer pattern** — why route/shortcut use placeholder layers:

> "We can't concatenate tensors at module-creation time — they don't exist yet. EmptyLayer is a placeholder. The actual concatenation/addition happens in `forward()` where we can index into stored layer outputs."

## Hour 3: Image Segmentation (A2-02-Image-Segmentation.ipynb)

### The framing

**What to say:**

> "Detection gives you a box. For a surgeon, a box around a tumor is useless — they need to know *which exact pixels*. That's segmentation."

| Task | Output | Example |
|------|--------|---------|
| Detection | Bounding box | Where is the car? |
| Semantic segmentation | Per-pixel class | Which pixels are road vs sky? |
| Instance segmentation | Per-pixel + per-object | Which pixels belong to *this* car vs *that* car? |

---

### FCN → U-Net (Cells 2–8)

**FCN insight:**

> "Classification CNNs destroy spatial information in FC layers. Replace FC with 1×1 convolutions — output is now a spatial map, not a scalar. Then upsample back to input resolution."

**U-Net — connect back to ResNet skip connections from A1:**

> "Remember ResNet skip connections? U-Net uses the same idea but for a different reason. ResNet skips to fix gradient flow. U-Net skips to preserve spatial detail — the encoder knows exactly where edges are at high resolution, and the decoder needs that information back."

```
Encoder: 256×256 → 128 → 64 → 32 → 16 (bottleneck)
Decoder:                        32 → 64 → 128 → 256×256
           ←──────── skip connections ────────→
```

**Why skip connections matter MORE for segmentation than classification:**

> "Classification only needs to know *what*. Segmentation needs to know *what* AND *exactly where*. Deep features = what. Shallow features = where. Skip connections bring both to the decoder."

---

### mIoU — connect back to IoU from Hour 1

**What to say:**

> "Remember IoU from Hour 1? mIoU is the same idea applied per pixel, averaged over classes."

$$\text{IoU}_c = \frac{TP_c}{TP_c + FP_c + FN_c} \qquad \text{mIoU} = \frac{1}{C}\sum_c \text{IoU}_c$$

> "Why not accuracy? If 90% of pixels are background, predicting all-background gets 90% accuracy and is useless. mIoU penalizes this — the background class gets IoU = 1.0 but foreground classes get IoU = 0, pulling the mean down hard."

---

### Mask R-CNN (Cell 3)

**Connect back to Faster R-CNN:**

> "Faster R-CNN = backbone + RPN + classification head. Mask R-CNN adds one more head: for every detected box, also predict a binary mask. Three heads, one backbone."

**RoI Align vs RoI Pooling:**

> "RoI Pooling rounds coordinates to integer pixels — 1px misalignment. Fine for boxes. Terrible for masks — 1px error at the boundary means wrong pixels. RoI Align uses bilinear interpolation, no rounding."

---

## Exercise Walkthrough Tips

**IoU notebook:**
- Make sure students can compute mAP by hand for a tiny example (2 classes, 5 predictions) before running code
- The DIoU-NMS question is important — students should understand *why* IoU-NMS fails for crowded pedestrian scenes

**A2-01 Ex1 (YOLOv4 cfg):** Key additions: Mish activation + CSP connections. Focus on Mish — it's not in PyTorch by default.

**A2-01 Ex2 (mAP on custom data):** Make sure they understand the IoU threshold matters — same predictions, different thresholds, very different mAP.

**A2-02 Ex1 (Skip connections ablation):** This is the most important exercise. Students should see a clear mIoU drop without skip connections. If the gap is small, they didn't train long enough.

**A2-02 Ex2 (Pretrained encoder):** Connect to A1 — same two-stage fine-tuning idea. Freeze encoder first, then unfreeze. With limited medical data, pretraining matters more than architecture choice.

## The Big Picture — Full Timeline

```
2014  R-CNN         "Use CNN for detection. Slow but it works."
        ↓
2015  Fast R-CNN    "Share the backbone. One CNN pass."
2015  FCN           "Replace FC → 1×1 conv. First pixel-level output."
2015  U-Net         "Skip connections bring back spatial detail."
        ↓
2016  Faster R-CNN  "Learn proposals with RPN. Two-stage fully learned."
2016  YOLO v1       "Skip proposals. One shot, one pass, real-time."
        ↓
2017  Mask R-CNN    "Faster R-CNN + mask head = instance segmentation."
        ↓
2018  YOLOv3        "Multi-scale detection. Anchors at 3 resolutions."
        ↓
2020  GIoU/DIoU/CIoU "Better box regression losses. CIoU now standard."
        ↓
2021+ DETR, DINO    "Transformers for detection. No anchors, no NMS."
```

**Closing question:**

> "A hospital wants pixel-level tumor outlines from MRI scans. They have 300 labeled scans. Which model and which training strategy?"
>
> Answer: U-Net with pretrained ResNet encoder (fine-tuned). YOLO gives boxes not masks. 300 samples → must use pretrained encoder. Two-stage: freeze encoder → train decoder → unfreeze all.
