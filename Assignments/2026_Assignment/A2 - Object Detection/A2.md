## 0.5 hr: IoU, GIoU, DIoU, CIoU, mAP (A2-00-IoU-and-mAP.ipynb)

**Papers:** [GIoU](https://arxiv.org/abs/1902.09630) — *Generalized Intersection over Union: A Metric and A Loss for Bounding Box Regression* · [DIoU/CIoU](https://arxiv.org/abs/1911.08287)

### Why start here

**What to say:**

> "Before we talk about any detection model, we need to agree on what 'correct' means. If a model draws a box around a dog — how do we decide if that's a good box or a bad one? That question has a surprisingly deep answer."

Everything in detection — anchor assignment, NMS, training loss, evaluation — is built on top of one concept: **IoU**.

---

### IoU

$$\text{IoU}(A, B) = \frac{|A \cap B|}{|A \cup B|}$$

**What to say:**

> "IoU ranges from 0 (no overlap) to 1 (perfect match). Pascal VOC says IoU ≥ 0.5 is a correct detection. COCO is stricter — it averages over IoU 0.5 to 0.95."

**Quick code demo:**

```python
def iou(boxA, boxB):
    xA = max(boxA[0], boxB[0]);  yA = max(boxA[1], boxB[1])
    xB = min(boxA[2], boxB[2]);  yB = min(boxA[3], boxB[3])
    inter = max(0, xB - xA) * max(0, yB - yA)
    areaA = (boxA[2]-boxA[0]) * (boxA[3]-boxA[1])
    areaB = (boxB[2]-boxB[0]) * (boxB[3]-boxB[1])
    return inter / (areaA + areaB - inter)

print(iou([10,10,50,50], [20,20,60,60]))   # 0.143
print(iou([10,10,50,50], [10,10,50,50]))   # 1.0
print(iou([10,10,50,50], [60,60,80,80]))   # 0.0
```

**Pause and ask:**

> "Two boxes have IoU = 0. What's the gradient of `L = 1 - IoU`?"
>
> Answer: Zero. Optimizer has no signal — this is IoU's fundamental problem as a loss function.

---

### GIoU → DIoU → CIoU

| Metric | What it adds | Fixes |
|--------|-------------|-------|
| **IoU** | Intersection/Union | — |
| **GIoU** | Penalizes wasted space in enclosing box | Zero gradient when no overlap |
| **DIoU** | Penalizes center-point distance | Slow convergence when box is inside GT |
| **CIoU** | Adds aspect ratio consistency | All three geometric factors together |

**GIoU:**
$$\text{GIoU} = \text{IoU} - \frac{|C \setminus (A \cup B)|}{|C|}$$

When boxes don't overlap, IoU = 0 but GIoU < 0 — gradient still flows.

**CIoU** — YOLOv4+ uses this as box regression loss: overlap + center distance + aspect ratio all in one.

**DIoU-NMS:** In crowded scenes, two people can have high IoU but different centers — standard NMS suppresses one incorrectly. DIoU-NMS is less aggressive.

---

### mAP

```
1. For each class, rank predictions by confidence (high → low)
2. For each prediction: IoU ≥ threshold + unmatched → TP, else → FP
3. Compute Precision-Recall curve
4. AP = area under PR curve
5. mAP = mean AP over all classes
```

- **VOC mAP**: single threshold (0.5), 11-point interpolation
- **COCO mAP**: average over 10 thresholds (0.5:0.05:0.95) — much stricter

### 1.1 R-CNN (2014) — Cell 3–4

**What to say:**

> "Before R-CNN, detection used hand-crafted features. R-CNN asked: what if we just run a CNN on every candidate region?"

**Selective Search** groups similar pixels into ~2,000 *plausible* candidate boxes per image (not random — covers ~99% of GT boxes).

**Pipeline:**
```
Image → Selective Search (~2,000 boxes)
      → warp each to 227×227 → AlexNet → 4096-dim feature
      → SVM classifier → class label
      → Bbox regressor → refined (x,y,w,h)
```

**3 separate losses — trained independently (key weakness):**

1. **CNN fine-tune** — softmax cross-entropy on warped crops
2. **SVM** — hinge loss per class (replaces softmax at test time — found to work better on the CNN features)
3. **Bbox regressor** — MSE on log-space offsets:
$$t_x = (G_x - P_x)/P_w, \quad t_w = \log(G_w/P_w)$$

**Why 3 separate?** Can't backprop through RoI warping — each region processed independently, no end-to-end training possible.

**Problems:** 2,000 CNN passes → 47s/image. Features must be cached to disk. No joint optimization.

**Code demo (cell 4):** simulates 2,000 proposals, loops CNN one-by-one to show the bottleneck.

---

### 1.2 Fast R-CNN (2015) — Cell 5–6

**Key insight:**

> "R-CNN ran the CNN 2,000 times. The image doesn't change — run CNN once, extract all regions from shared feature map."

**Pipeline:**
```
Image → CNN backbone (1×) → shared feature map
      ← Selective Search → ~2,000 proposals
      → RoI Pooling → fixed 7×7 per proposal
      → FC layers → class + bbox (jointly trained)
```

**RoI Pooling:** divide each proposal's feature region into 7×7 grid, max-pool each cell → fixed-length feature regardless of proposal size.

**Multi-task loss — first end-to-end detector:**
$$\mathcal{L} = \mathcal{L}_{\text{cls}}(p, u) + \lambda \cdot \mathbf{1}[u \geq 1] \cdot \mathcal{L}_{\text{loc}}(t^u, v)$$

- $\mathcal{L}_{\text{cls}} = -\log p_u$ — cross-entropy over K+1 classes
- $\mathcal{L}_{\text{loc}}$ — smooth L1 (Huber) on box offsets, **foreground only** ($u \geq 1$, skip background)
- smooth L1 more robust than MSE: quadratic for small errors, linear for large

**9× faster training, 213× faster testing.** Still bottlenecked by Selective Search (~2s CPU).

**Code demo (cell 6):** backbone runs once, RoI pool extracts from shared map, shows time difference.

---

### 1.3 Faster R-CNN (2016) — Cell 7–8

**Key insight:**

> "The feature map already knows where things are. Why use a CPU algorithm to find proposals? Train a small network on the feature map instead."

**Pipeline:**
```
Image → CNN backbone → shared feature map
            ├── RPN → objectness + proposals  (GPU, ~10ms)
            └── RoI Pooling → FC → class + bbox
```

**Anchors:** at each feature map location, RPN considers k=9 anchor shapes (3 scales × 3 ratios). Positive: IoU > 0.7, Negative: IoU < 0.3.

**Two losses trained jointly:**

**RPN loss:**
$$\mathcal{L}_{\text{RPN}} = \frac{1}{N_{\text{cls}}} \sum_i \mathcal{L}_{\text{cls}}(p_i, p_i^*) + \lambda \frac{1}{N_{\text{reg}}} \sum_i p_i^* \cdot \mathcal{L}_{\text{reg}}(t_i, t_i^*)$$

- $\mathcal{L}_{\text{cls}}$ = binary CE (object vs background)
- $\mathcal{L}_{\text{reg}}$ = smooth L1 on offsets, positive anchors only

**Detection head loss** — same as Fast R-CNN:
$$\mathcal{L}_{\text{det}} = \mathcal{L}_{\text{cls}}(p, u) + \lambda \cdot \mathbf{1}[u \geq 1] \cdot \mathcal{L}_{\text{loc}}(t^u, v)$$

**Total:** $\mathcal{L} = \mathcal{L}_{\text{RPN}} + \mathcal{L}_{\text{det}}$ — backbone shared, both losses backprop together.

| Model | Proposal | Speed | Loss |
|---|---|---|---|
| R-CNN | Selective Search + 2000× CNN | 47s | 3 separate |
| Fast R-CNN | Selective Search + 1× CNN | ~2s | 1 joint (cls + smooth L1) |
| Faster R-CNN | RPN on GPU | ~0.2s | 2 joint (RPN + det) |

**Code demo (cell 8):** RPN generates 56×56×9 = 28,224 anchors in one pass, speed table printed.

### 1.4 YOLO (Cells 9–58)

**What to say:**

> "Redmon looked at the whole two-stage pipeline and asked: what if we skip proposals entirely?"

**The YOLO idea:** one network predicts all boxes and classes simultaneously from the whole image.

```
Image (416×416)
    ↓ single forward pass
Grid: 13×13 (large), 26×26 (medium), 52×52 (small objects)
    ↓ each cell predicts B × (4 coords + 1 conf + C classes)
```

**Grid cell responsibility:** the cell whose center contains the GT box center is responsible for predicting that object.

**YOLOv3 multi-scale:** 3 scales handle different object sizes — directly improves COCO mAP (which averages IoU 0.5–0.95) without sacrificing speed.

**Darknet cfg → PyTorch (Cells 18–58):**

> "Darknet is the C framework YOLO was trained in. The config file is a recipe — each block is a layer."

**EmptyLayer pattern:** route/shortcut blocks use placeholder layers — actual concat/addition happens in `forward()` where stored layer outputs can be indexed.

**Training on COCO (Cells 59–81):** uses `fiftyone` to download COCO validation set, `albumentations` for augmentation, trains YOLOv3 from pretrained weights.

## 1 hr: Image Segmentation (A2-02-Image-Segmentation.ipynb)

### The framing

**What to say:**

> "Detection gives you a box. For a surgeon, a box around a tumor is useless — they need to know *which exact pixels*. That's segmentation."

| Task | Output | Example |
|------|--------|---------|
| Detection | Bounding box | Where is the car? |
| Semantic segmentation | Per-pixel class | Which pixels are road vs sky? |
| Instance segmentation | Per-pixel + per-object | Which pixels belong to *this* car vs *that* car? |

---

### FCN → U-Net (Cells 2, 7–8)

**FCN insight:** replace FC layers with 1×1 convolutions → spatial output map → upsample back to input resolution. Problem: upsampling from tiny feature map loses spatial detail.

**U-Net — walk through the diagram in notebook (cell 2):**

Point to each part:
- **Left (encoder):** 4× DoubleConv + MaxPool. Channels 1→64→128→256→512. Spatial halves every stage. Learns *what* is in the image.
- **Bottom (bottleneck):** 1024ch, smallest spatial size. No skip connection — pure semantic compression.
- **Right (decoder):** up-conv 2×2 doubles spatial. Concat skip connection → DoubleConv. Recovers *where* things are.
- **Gray arrows (copy and crop):** the skip connection. Original paper crops because no padding — modern `padding=1` means sizes match exactly, no crop needed.
- **Top right:** Conv 1×1 maps 64ch → n_classes.

**Connect to ResNet from A1:**

> "ResNet skip: add input to output (residual). U-Net skip: *concatenate* full encoder feature map — brings back complete high-res detail, not just a residual."

**Why skips matter more for segmentation:**

> "Classification only needs *what*. Segmentation needs *what* AND *exactly where*. Without skip connections the decoder tries to reconstruct exact pixel boundaries from a blurry bottleneck."

**Pause and ask:**

> "Which skip hurts most when removed — stage 1 (64ch, highest resolution) or stage 4 (512ch, lowest resolution)?"
>
> Answer: Stage 1 — carries the finest spatial detail (exact edges). Stage 4 context is already encoded in the bottleneck.

**Two model variants in notebook (cells 8–12):**

| Model | Encoder | Skip connections | Pretrained |
|---|---|---|---|
| `UNet` | Custom DoubleConv | ✅ | ❌ |
| `UNetResNet18` | ResNet-18 | ✅ | ✅ ImageNet |

Switch with `MODEL_TYPE = 'scratch'` or `'resnet18'` in cell 12.

---

### mIoU (Cell 2)

$$\text{IoU}_c = \frac{TP_c}{TP_c + FP_c + FN_c} \qquad \text{mIoU} = \frac{1}{C}\sum_c \text{IoU}_c$$

> "Why not accuracy? 90% background → predicting all-background = 90% accuracy and is useless. mIoU penalizes this hard."

---

### Mask R-CNN (Cell 3)

**Connect to Faster R-CNN:**

> "Faster R-CNN = backbone + RPN + classification head. Mask R-CNN adds one more head: predict a binary mask for every detected box. Three heads, one backbone."

**RoI Align vs RoI Pooling:**

> "RoI Pooling rounds to integer pixels — 1px misalignment. Fine for boxes. Terrible for masks. RoI Align uses bilinear interpolation, no rounding."

## The Big Picture — Full Timeline

```
2014  R-CNN         "CNN for detection. 3 separate models, 47s/image."
        ↓
2015  Fast R-CNN    "Shared backbone + joint loss. 2s/image."
2015  FCN           "Replace FC → 1×1 conv. First pixel-level output."
2015  U-Net         "Skip connections recover spatial detail."
        ↓
2016  Faster R-CNN  "RPN replaces Selective Search. 0.2s/image."
2016  YOLO v1       "Skip proposals entirely. Single-shot, real-time."
        ↓
2017  Mask R-CNN    "Faster R-CNN + mask head = instance segmentation."
        ↓
2018  YOLOv3        "Multi-scale detection. 3 anchor scales."
        ↓
2020  GIoU/DIoU/CIoU "Better box regression losses. CIoU now standard in YOLOv4+."
        ↓
2021+ DETR, DINO    "Transformers for detection. No anchors, no NMS."
```

**Closing question:**

> "A hospital wants pixel-level tumor outlines from MRI scans. 300 labeled scans. Which model and training strategy?"
>
> Answer: U-Net with pretrained ResNet-18 encoder. YOLO gives boxes not masks. 300 samples → must use pretrained encoder. Strategy: freeze encoder → train decoder → unfreeze all.
